Web-first system shape

The browser can leave. The observatory cannot.

A rig-local service owns hardware and long-running work. Local and remote browsers consume the same narrow product contract without inheriting Electron IPC or direct device access.

Core invariant

No browser lifecycle—refresh, navigation, sleep, disconnect—can accidentally pause, cancel, or become authoritative for an observing run.

Local shape

Desktop / tablet / phone browser
↔
Typed HTTP + streamed snapshots
↔
Rig-local observatory service
↔
Rig + storage + processors

The service starts independently, serves the frontend, owns the active run, and remains useful with zero connected browsers. The browser owns navigation and draft presentation—not hardware state or workflow progress.

Simple transport first

  • HTTP commands carry intent, expected revision, controller lease, and idempotency/correlation identifiers.
  • Streamed snapshots and events deliver current truth, run progress, warnings, and new frame availability.
  • Ordinary asset HTTP serves bounded thumbnails and previews; original frames are explicit downloads.

Effect Schemas are candidate canonical transport contracts. Unknown input is decoded at both service and browser boundaries. Framework choice stays deferred until contract spikes expose actual needs.

Remote sharing without a custom bridge

Friend at public HTTPS URL
↔
Linux server · auth + proxy
↔
Private outbound tunnel
↔
Rig-local service

The observatory side initiates the private connection outward. No inbound home-network port is required. The public entry point authenticates a small trusted group and proxies the same-origin application.

Remote clients receive status, telemetry, thumbnails, and right-sized previews. Raw camera frames and processing remain near the rig unless explicitly requested.

Shared control stays visible

  1. A trusted viewer requests control.
  2. The owner grants one exclusive controller lease.
  3. Every client displays the current controller and connection freshness.
  4. Only the service authorizes mutations; hiding buttons is not authorization.
  5. The owner can visibly take control back.

The initial phone client is read-only. This is a product-scope choice, not a claim that phone browsers are inherently unsafe.

Proportionate security baseline

Managed authentication, HTTPS, one visible control lease, typed product operations, outbound rig connectivity, server-side authorization, and bounded library access. No local password database, enterprise organization hierarchy, policy language, or arbitrary remote shell.
