Candidate product model

The service owns truth. The UI owns attention.

This study translates the first interface prototypes into backend responsibilities. It deliberately distinguishes durable run truth, device reports, derived presentation, and browser-local state.

Model test

If a UI claim cannot be reconstructed from a current snapshot plus its relevant evidence, either the interface is inventing truth or this model is incomplete.

Four kinds of state

Service-owned

  • Approved plan snapshot
  • Active run phase
  • Command correlation
  • Control lease
  • Warnings and approvals

Device-reported

  • Physical position
  • Tracking state
  • Camera temperature
  • Exposure activity
  • Capability state

Derived

  • Night fit
  • Frame trends
  • Suggested action
  • Mutation impact
  • UI urgency

Client-local

  • Workspace
  • Selected row
  • Open inspector
  • Draft edits
  • Compare layout

Changing workspaces or closing every browser therefore has no authority over an active run. Device claims are inputs, not substitutes for run history; image evidence can disprove an accepted movement command.

Recover is a superseding phase reachable from Acquire, Capture, or Verify. It does not erase the interrupted phase or its partial evidence. Recovery chooses a bounded path back, skip, stop, or park.

The classifier is one domain decision consumed everywhere. The renderer must not recreate it from button names or current phase.

Snapshot and reconnect

A reconnecting browser receives a current snapshot containing the active run revision, phase, current work, latest trusted device state, warnings, approvals, controller identity, and references to recent evidence. Incremental events begin only after that snapshot version.

Durable history answers “how did we get here?” Transient progress answers “what is changing now?” Replaceable telemetry answers “what is the latest reading?” They should not share one undifferentiated event stream.

Questions deliberately unresolved

  • Exactly how much run history persists across a service restart?
  • When does a disconnected controller lease expire, if an unattended run continues?
  • Are plan revisions first-class entities or an append-only record on NightPlan?
  • Which frame-quality recommendations require user approval versus plan policy?
  • Does Recover wrap the prior phase or remain a peer phase with an explicit resume target?
